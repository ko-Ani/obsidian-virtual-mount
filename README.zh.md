# Virtual Mount（虚拟挂载）

**把一个真实文件夹（或单篇笔记）镜像显示到文件浏览器里的任意目录下 —— 不移动、不复制、不用符号链接。**

```
磁盘（唯一真实数据）              Obsidian 文件浏览器
03-资料/项目A/                   01-进行中/
├── alpha.md              ──▶    ├── 会议记录.md
├── beta.md                      └── 项目A ↪            ← 虚拟挂载
└── 子目录/                          ├── alpha
                                     ├── beta
                                     └── 子目录
```

虚拟节点和原生文件夹长得一模一样：点开就是真实文件，两边同步编辑，源目录里增删文件镜像立刻跟着变。
**磁盘上不会创建任何目录**，映射关系存在插件自己的 `data.json` 里。

[English](README.md)

## 功能

- **文件夹镜像**：把整个文件夹挂到任意目录下，源目录的增 / 删 / 改名实时同步。
- **单文件挂载**：同一篇笔记可以同时出现在多个位置。
- **右键入口**：右键（手机上长按）任意文件夹 → `虚拟挂载到…`，选挂载点、改显示名称。
- **原生外观**：沿用核心的 `tree-item` / `tree-item-self` / `tree-item-flair` 类名，主题和悬停效果都是原生的。
- **跟随重命名**：源文件夹改名或移动，挂载配置自动改写路径，不会失效。
- **零磁盘痕迹**：不用 symlink、不用 junction、不产生重复文件。
- **桌面端 + 移动端**：同一套代码；长按菜单、剪贴板降级方案都做了适配。

## 为什么不用符号链接？

Obsidian 的索引来自磁盘扫描：`TFile.path` 就是真实路径，**没有任何 API 能往索引里加虚拟路径**；
而且官方明确会忽略「仓库内一个文件夹指向另一个」的 symlink，因为同一文件出现两份会让 `[[双链]]` 产生歧义（[帮助文档](https://obsidian.md/help/symlinks)）。

所以本插件是一个**视图层**：读真实的 `TFolder` 数据，在原生文件浏览器里画出等价节点。
虚拟路径只是视觉上的，文件始终保留真实路径——这正是两边能同步的原因。

## 安装

**社区插件（审核通过后）**：设置 → 第三方插件 → 浏览 → 搜索 “Virtual Mount”。

**手动安装：**

1. 从最新 Release 下载 `main.js`、`manifest.json`、`styles.css`；
2. 放进 `<你的仓库>/.obsidian/plugins/virtual-mount/`；
3. 重启 Obsidian，在 设置 → 第三方插件 里启用 **Virtual Mount**。

**BRAT**：添加 `ko-Ani/obsidian-virtual-mount` 作为 beta 插件。

## 使用

**右键**文件夹 → `虚拟挂载到…` → 选「挂载到」、改「显示名称」→ 挂载。
右键单篇笔记则显示 `虚拟挂载到…（单文件）`。

**设置页**有完整编辑器（类型 / 源路径 / 挂载点 / 名称）、挂载列表（可单独启用停用）和显示选项。

命令面板（`Ctrl/Cmd+P`）：

- `添加虚拟挂载…`
- `把当前文件挂载到…`
- `把当前文件所在的文件夹挂载到…`
- `刷新虚拟挂载`

交互：

- 单击虚拟笔记 → 打开真实文件（`Ctrl/Cmd+单击` 或中键 → 新标签）
- 右键虚拟节点 → 定位真实位置 / 复制真实路径 / 取消挂载
- 点击虚拟文件夹 → 折叠展开，状态会记住

## 实现原理

Obsidian 1.6+ 的文件树是虚拟化列表：滚动时 `setChildrenInPlace()` 会整体替换 `.nav-folder-children` 的子节点，
塞进去的第三方节点会被清掉。因此插件：

1. 通过标题上的 `data-path` 找到真实文件夹元素；
2. 在 `.nav-folder` 下另建一个平级容器 `.vm-children`（沿用 `tree-item-children` 的缩进样式，但只由插件管理）；
3. 仅在源数据变化时重建，核心重绘后由 `MutationObserver` 补注入；
4. 在 `click` / `auxclick` / `contextmenu` 上 `stopPropagation`，核心的委托事件永远不会碰到虚拟行。

右键菜单项通过 `workspace` 的 `file-menu` 事件添加，并按 `file-explorer-context-menu` 过滤来源。

## 移动端

手机端跑的是同一份 bundle、同一套文件树 DOM，所以挂载显示完全一致。
长按会触发同一个右键菜单；「复制真实路径」在 `navigator.clipboard` 不可用时自动退回 `execCommand`。

`isDesktopOnly` 为 `false`。

## 兼容性

- Obsidian **1.6.0+**，桌面端与移动端。
- 针对 **1.8.9** 实测（DOM 结构从发布包的 `app.js` 反查确认）。

## 已知限制

- **只读导航**：虚拟行不能拖拽、重命名、删除——请到真实位置操作（右键可一键定位）。
- **虚拟路径不可被链接解析**：`[[01-进行中/项目A/alpha]]` 找不到；链接永远指向真实路径。
- **不进搜索 / 快速切换 / Graph**：这些走后端索引，只认识真实路径。
- **挂载块固定在目标文件夹顶部**：核心的虚拟列表管理着其余子节点，无法按字母序插进中间。
- **升级风险**：依赖核心 DOM 结构，Obsidian 大版本升级后可能需要适配。

## 开发

```bash
pnpm install
pnpm dev      # 监听构建
pnpm build    # 类型检查 + 生产构建 → main.js
pnpm test     # jsdom 测试：DOM 注入 / 插件入口 / i18n
```

DOM 测试复刻了 1.8.x 的真实树结构（从 `app.js` 提取），包括虚拟滚动的整体替换行为。
